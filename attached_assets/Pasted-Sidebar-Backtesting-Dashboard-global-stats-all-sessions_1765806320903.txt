5. Full‑screen chart window (replay workspace)
This is where the backtesting actually happens. It opens from:

Dashboard → Go to chart (session row).

Sessions → Go to chart (top right button).

Assume route like /backtesting/chart?sessionId=..., rendered full‑screen.

5.1 Initialization
On load:

Fetch Session and its Trades using sessionId.

Configure TradingView Advanced Chart:

Set symbol from session.

Allow all built‑in timeframes (1m/5m/15m/1h/4h/1D, etc.) – no need to store timeframe on session.

Constrain visible historical data to [fromDate, toDate].

Activate replay mode starting at progressPointer.

Re‑draw all existing trades:

Plot entry/exit markers and SL/TP lines based on stored trades.

Optionally color code winners/losers.

5.2 Layout inside chart window
Top bar

Left:

Symbol (big label).

Session name.

Date range.

Center:

Current balance and cumulative PnL.

Right:

Replay controls: Play / Pause, Step forward, Speed selector.

Button: End session (marks it completed and optionally jumps pointer to toDate).

Button: Back (returns to previous view / route).

Main area

TradingView Advanced Chart in replay mode, using all standard toolbar/timeframe controls.

Your custom buttons overlay:

“New Long” and “New Short” to create trades.

Optional “Close all” or “Close selected trade”.

Side panel (optional)

List of open trades with quick close button.

List of recently closed trades.

Small live equity mini‑chart.

Journal textarea for this session or current trade.

5.3 Replay + trades behaviour
Replay progress

When user plays or steps the chart:

The chart moves bar by bar inside [fromDate, toDate].

After each bar (or at intervals), update progressPointer with the current bar’s timestamp/index.

Do a light auto‑save so if the window is closed or crashes, progressPointer is up to date.

Placing trades

User clicks “New Long” or “New Short”.

Interaction options (choose what fits TradingView API best):

Click on the chart to set entry, then drag for SL/TP, or

Pop a small modal for numeric entry and draw objects afterward.

On confirmation:

Create Trade:

sessionId, side, size, entryPrice, sl, tp, openedAt = current bar time.

Draw trade markers on chart.

Save trade immediately.

Closing trades

Automatic close:

If price hits SL or TP during replay:

Set exitPrice, closedAt, pnl, rr.

Update currentBalance for Session.

Mark trade as closed and update chart markers.

Manual close:

User selects an open trade in side panel or via marker and chooses “Close”.

Close at current bar price/time, compute PnL, update Session.currentBalance.

All trade and balance updates are persisted right away.

5.4 Closing and resuming
User closes chart window

Before leaving:

Save progressPointer (latest bar).

Ensure all trades and currentBalance are persisted.

Session status:

Remains "active" unless user explicitly hits End session.

End session sets status = "completed" and (if you want) sets progressPointer = toDate.

User reopens chart window later

From Dashboard or Sessions → Go to chart:

Reload session, trades, progressPointer.

TradingView:

Same symbol.

Same [fromDate, toDate].

Replay starts exactly at saved progressPointer.

All trades redrawn, balance and PnL in the header reflect last state.

User can continue replaying forward, adding trades, etc., until the full date range is exhausted or session is ended.

6. How everything ties together
Create: User defines a single‑pair session with a date range and balance.

Trade: User opens the full‑screen chart, replays the data, takes trades; everything (progress, trades, PnL) is persisted.

Review:

Dashboard: global stats + list of all sessions with direct “Go to chart”.

Sessions: pick one session, see analytics + trades; also has “Go to chart”.

Resume: Any time “Go to chart” is clicked for a session, the chart resumes exactly from where replay stopped, using stored progressPointer and trades.

This is the full, coherent flow as discussed. Review this structure, and then you can refine specific UI details or naming as you start implementing.
